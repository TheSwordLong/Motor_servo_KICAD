# 四路机器人电机固件：协议、使用和验收

连续相对运动约定：[M2 +20°、+20°、−20°、−20° 的 Modbus/CAN 操作](Robot_免序号操作.md#repeated-angle)。[robot.c](../BSP/robot.c) 的 MOVE 用当前 `position` 加本次角度转换的有符号 FG 步数生成 `target`，不是累加旧目标，也不按一圈取模。同一路忙时拒绝，无排队；新动作前不重复 ZERO/CONFIG。每次确认本次请求接受后等待 DONE=5、fault=0、valid=1，再核对位置与保存。理想累计 +20°/+40°/+20°/0° 需与实际测量分开记录，整数换算和余转误差可能累积。

验收增加四次串行运动、运行中再次 MOVE 被拒绝、停止后重新暂存 MOVE、丢应答先查状态等场景；每条请求记录实际序号、目标/当前角度、独立测量、完成和保存状态，流程见[完整测试步骤](Robot_完整测试流程.md)。本次文档更新不是硬件验收通过记录。

启动保护更新：Reset_Handler 在 RAM 初始化后、SystemInit 时钟等待前调用停止 GPIO，main 再次保持停止；复位/供电未建立阶段仍需电路保证，不能据此宣称实体上电不动。见[上电短转排查与实测步骤](Robot_上电短转排查.md)。

免序号操作：执行请求序号填 0000，板子自动分配非零编号；非零请求保留原去重。完整帧与新旧兼容说明见[免序号操作](Robot_免序号操作.md)。重复零序号提交可能再次运动，不能自动重试。

操作补充：[11 个功能的作用与条件](Robot_Modbus与CAN使用手册.md#function-guide)、[错误码及逐项恢复](Robot_Modbus与CAN使用手册.md#error-recovery)、[可复制的查询/恢复报文](Robot_免序号操作.md#recovery-steps)。

首次安装推荐流程：读取 UID → 四路批量自检 → 等待停止及保存、记录结果 → 按实际硬件填写四路减速比等参数 → 一次 CONFIG 保存到驱动板 Flash → 读回核对 → 手动设零 → 角度控制。详见[首次使用与保存职责](Robot_Modbus与CAN使用手册.md#commissioning)。这是推荐流程，不是 CONFIG 的强制前置条件；自检不能识别减速比。

驱动板持久保存并使用四路减速比，上位机按 UID 编辑和备份，发送角度时不重复乘减速比。暂存写入不是保存，CONFIG 成功已保存完整配置，无需额外 SAVE；SAVE 不提交暂存配置。读回四路已应用值和存储标志后才确认同步。修改减速比、标签或反相使位置失效，恢复绝对参考须重新设零，相对 MOVE 无此要求；修改启用、标签、减速比或反相也清除对应 RAM 自检结果，如需检测历史应在 CONFIG 前留档。

直接发送报文的操作步骤见 [Modbus 与 CAN 使用手册](Robot_Modbus与CAN使用手册.md)，包含输出轴 +20°/−20°控制及全部命令速查。

版本：命令协议2、寄存器/存储格式1。本文描述当前机器人固件；[基础版本验证记录](history/Robot_验证记录.md)与[自检版本验证记录](history/Robot_自检验证记录.md)分别记录对应版本的软件验证和未执行的硬件测试。串口使用二进制 Modbus，不支持旧 ASCII 电机调试命令。

当前包括往返电机响应自检，存储格式和原接口编号不变。使用方式、HEX 示例及本次验证见[四路电机响应自检](Robot_电机自检.md)；上述旧验证记录中的体积、哈希对应自检加入前的版本。

## 1. 已确认的行为

首次安装推荐流程：读取 UID → 无需配置的四路批量自检 → 等待停止及保存、记录检测结果 → 按实际硬件填写四路减速比等配置 → 一次 CONFIG 提交到驱动板 Flash → 读回核对 → 手动设零 → 角度控制。完整说明见[首次使用与保存职责](Robot_Modbus与CAN使用手册.md#commissioning)。自检不会识别减速比，不是 CONFIG 的强制前置条件。

四路减速比由驱动板持久保存并执行换算，上位机按 UID 编辑和备份。暂存写入不是保存，CONFIG 成功即已保存完整配置，不需要再发 SAVE；SAVE 不提交暂存配置。读回四路已应用值与存储标志后才确认同步。配置减速比/标签/反相变化使位置失效，恢复绝对参考时须手动设零，相对 MOVE 不要求；启用/标签/减速比/反相变化也清除对应 RAM 自检结果，上位机如需历史记录应在提交前留档。

- 每块板四路固定 M1～M4，不能交换逻辑编号与定时器的映射。协议通道字段是 `0～3`，上位机脚本显示 `1～4`。
- 每路独立配置：启用、关节标签、减速比 `516/82/290`、正方向反相、减速前巡航目标 RPM。减速比允许重复。
- 关节标签仅标识机器人部位，不改接线。头部一个，大臂、小臂、手掌各左右两个；共七个关节，通常需两块板。
- 相对输出轴角度，单位 `0.1°`，范围 `-3600～3600`，即 `±360°`。目标在接受命令时由当前位置计算；累计位置不按一圈取模。零角度是空操作。
- 同一路忙时拒绝新运动，四路可以独立同时运行；没有动作队列或多轴同步轨迹。
- 默认巡航目标 `8000 RPM` 是减速前电机转速，接近目标时降低目标转速。允许配置 `400～8000 RPM`，该区间是本版软件的调试边界，未实测其可控性。
- 到位允许误差 `±5°`。软件按 FG 位置判断；机械实际精度、刹车距离、减速器回差仍须实测。没有固定到位时间承诺。
- 无零点传感器。所有电机停止后，上位机对指定通道手动设零；操作不转动电机。
- Modbus RTU/CH340 TTL 与 CAN 自定义协议二选一。初始 Modbus；切换协议和通信地址保存后下次启动生效。
- 运行中的有限角度动作在通信丢失后继续，受 FG 超时和运动总超时约束；未加入心跳断联停机策略。

### 固定引脚与信号

来源：[motor_pins.h](../BSP/motor_pins.h)、[pwm.c](../BSP/pwm.c)、[capture.c](../BSP/capture.c)、用户提供的 BLDC3650 接线图和电平转换说明。以下不是板上实测结果。

| 通道 | PWM | DIR | BRAKE | FG |
|---|---|---|---|---|
| M1 | PD12 / TIMER3_CH0 | PE15 | PE13 | PB10 / TIMER1_CH2 |
| M2 | PD13 / TIMER3_CH1 | PC5 | PA7 | PE11 / TIMER0_CH1 |
| M3 | PD14 / TIMER3_CH2 | PD3 | PD2 | PB4 / TIMER2_CH0 |
| M4 | PD15 / TIMER3_CH3 | PB8 | PB5 | PA0 / TIMER1_CH0 |

- 电机端 PWM **高停止、低运行**；用户确认 PWM 通路为同相 3.3V→5V 转换。本版占空比表示低电平时间比例：`0‰=持续高/停止`，`1000‰=持续低`。控制器运行限幅 `950‰`，底层接口支持 `0～1000‰`。
- PWM 默认 25 kHz，四路共享频率，可在全部停止时改为 20～30 kHz；各路占空比独立。改频会先停止四路 PWM。
- 电机端 DIR：低 CW，高 CCW。BRAKE：低刹车，高释放。DIR/BRAKE 板上转换通路是否同相，仍需核对。
- 先停止 PWM 再刹车；变向须等待原动作停止和静止判断通过。释放刹车或设置方向本身不启动电机。
- 入口最先驱动 PWM 高、BRAKE 低；CPU 故障处理也强制此状态。上电复位至进入代码前的电平仍取决于外部电路。
- 单路 FG 为 NPN 集电极开路，每减速前一圈 **6 个上升沿**。仅有 FG 单线，不能视为可独立识别转向的 AB 相编码器。位置符号来自运动命令，有效减速比下非预期活动累计>10°或捕获错误会使位置失效；≤10°不报故障4，未配置不触发本故障，捕获错误保护仍在。容忍范围内、不改变位置有效性且不计入有符号位置；静止不清累计；重启、成功清故障或设零清零；本版每次超限事件、自动恢复及人工调整进入也重置相关累计。自检中其他通道同样按此阈值处理，正常运动反馈完整计数。详见 [阈值与验证](Robot_FG调试观察.md)。
- 当前 FG 引脚启用 MCU 上拉；实际外部上拉电压、电平转换、接地须上板检查。

| 减速比 | 输出一圈 FG 数 | 单个 FG 对应输出角度 |
|---|---:|---:|
| 516 | 3096 | 约 0.1163° |
| 82 | 492 | 约 0.7317° |
| 290 | 1740 | 约 0.2069° |

## 2. 身份、配置和保存

只读序列号来自 MCU 的完整 96 位 UID：`0x1FFFF7E8`、`0x1FFFF7EC`、`0x1FFFF7F0`，按地址递增、每个 32 位字高位在前，显示为 24 个十六进制字符。Modbus 地址、CAN 节点号和关节标签都不替代 UID。

标签：`0=未分配，1=头部，2=左大臂，3=右大臂，4=左小臂，5=右小臂，6=左手掌，7=右手掌`。固件拒绝本板重复的非零标签；[上位机工具](../tools/robot_host.py)校验整机清单中的重复标签、重复 CAN 节点号。换板 UID 不同，需要重新绑定。

出厂空白记录：四路禁用、标签 0、减速比 0、零点无效。先提交完整配置，再在实际参考姿态设零，才允许运动。修改减速比、标签或方向反相会使对应零点失效；改 RPM、使能或 PWM 频率不自动改变已知零点。

### 保存建议与本版实现

[robot_store.c](../BSP/robot_store.c)使用最后两个 2 KiB Flash 页：`0x0807F000～0x0807FFFF`。链接区缩为 508 KiB；每条记录 256 字节，每页 8 条。记录含版本、长度、递增序号、dirty 标志、完整配置、四路位置/有效位、请求序号、CRC32 和最后写入的提交字。先写正文并读回校验，再写提交字；写满后擦另一页，保留最近一次已提交记录所在页。

1. 第一条动作离开全静止状态前，先保存 `dirty=1`；保存失败则拒绝启动。
2. 已有通道运动时，其他通道可加入；此时不写/擦 Flash。
3. 单路结束先更新 RAM。所有通道均停止、连续 500 ms 未收到 FG 后，统一保存位置并清 `dirty`。
4. 正常保存完成后，重启恢复位置；成立条件是用户确认的**断电期间轴不被外力转动**。
5. 运动或未完成保存期间断电，最后完整记录通常仍为 dirty：旧位置仅供查询，四路零点全部失效，绝不自动恢复运动；满足互锁后允许新的相对 MOVE，恢复绝对参考才需要手动设零。
6. 写入中断且新记录没有完整提交时，使用旧完整记录。运动完成后的写入中断会保留旧 dirty 记录；首次启动前的 dirty 写入失败不会已经放行运动。
7. 保存前后检测到意外 FG 时拒绝启动并尝试留下 dirty 记录。外力恰在写入、欠压或掉电瞬间介入的机械位置不能由软件绝对保证；位置可信需要静止窗口、稳定供电和无外力条件。

推荐目前采用此“每批动作结束后保存”策略，不要逐脉冲写 Flash。每批通常两条记录，每页约每八批发生一次擦除；实际寿命应按芯片数据手册保证值和每日动作次数评估。若需要高频长期运动、任意时刻断电保留实时位置，建议后续增加 FRAM/掉电保持能源或绝对值编码器；本版未虚构这些硬件。

整片擦除、旧版固件覆盖保留区会丢失配置和零点，UID 不受影响。新固件升级应保留这两页，并保持存储格式兼容。

## 3. Modbus RTU 寄存器

接口：USART0 PA9 TX / PA10 RX，CH340 TTL，`115200 8N1`。不是 PA2/PA3 的 RS-485；不能把多块 CH340 的 TX 直接并接。每块板独立串口连接。无日志、无字符串回显、无旧电机调试命令。

支持功能码 `03/06/10(hex)`；地址默认 1，可配置 1～247。地址 0 广播不执行、不回复。错误 CRC、其他站号不回复。最多 256 字节 ADU；03 最多 125 寄存器，10 最多 123 寄存器。主站逐次请求、等待回复，超时建议至少 1.5 s（静止时 Flash 擦写可能增加延迟）。接收用 ISR 时间戳检测 750 μs 字节间超时和 1750 μs 帧间隔；溢出或串口错误丢弃整帧，不把残帧当新命令。

下表是 **PDU 零基地址，十六进制**，不是 40001 记法。每个寄存器 16 位，高字节先发；32 位有符号值为二进制补码、高寄存器在前。CRC16 低字节先发。空洞地址返回异常 02，不要跨空洞批量读取。

| 0001 | R | 本次启动选中的协议，0 Modbus / 1 CAN |
| 0002 | R | 当前 Modbus 地址 |

### 每路寄存器

固定基址：**M1=0100，M2=0140，M3=0180，M4=01C0**。下表偏移以十六进制表示。

| 偏移 | 访问 | 含义 |
|---|---|---|
| +00～+04 | R | 已应用：enabled、role、gear、inverted、rpm |
| +08～+0C | R/W | 对应五项暂存配置；CONFIG 后统一验证/保存/应用 |
| +10 | R | 状态 |
| +11 | R | 故障码 |
| +12 | R | 零点/当前位置有效位 |
| +13 | R | 刹车，1 刹车、0 释放 |
| +14 | R | 当前 DIR 逻辑电平，0 CW、1 CCW |
| +15 | R | PWM 低电平占空比，‰ |
| +16 | R | 减速前 RPM；最后脉冲超过 250 ms 则显示 0 |
| +18～+19 | R | 累计输出轴角度 int32，0.1° |
| +1A～+1B | R | 有符号累计 FG 计数 int32，位置的原始表示 |
| +1C～+1D | R | 当前/最近目标输出角度 int32，0.1° |
| +20 | R | 最近自检状态，0～7，见下文 |
| +21 | R | 自检原因，0～10，见下文 |
| +22～+23 | R | 本次累计 FG 脉冲数（含余转），uint32 |
| +24 | R | 去程释放刹车至停止的时间，ms，uint16；返程时间见 +29 |
| +25～+26 | R | 自检完成时系统运行时间，ms，uint32；非日期时间 |
| +27 | R | 本次自检请求序号 |
| +30 | R | 手动模式：0关闭、1手动中、2退出等待 |

例如 M3 角度用 03 读 `0198` 起两个寄存器。单次 03 的数据来自同一次业务状态；中断只更新 FG 缓冲，不能撕裂该应答中的 32 位位置。不同请求之间可能发生运动，不能当作同一瞬间四路轨迹。长时间累计角度若超 int32 显示范围会饱和，原始脉冲仍可查询；原始计数越界会停机并使位置无效。

### 操作码和结果

| 操作码 | 名称 | 参数及条件 |
|---:|---|---|
| 1 | CONFIG | 全静止；验证全部暂存参数，保存后应用。通信协议/地址下次启动生效 |
| 2 | ZERO | 全静止，指定通道已有有效减速比；位置置零并保存，清该路故障 |
| 3 | MOVE | 指定通道，int32 相对角度 0.1°，-3600～3600；要求启用、有效减速比、无故障；相对运动不要求有效零点 |
| 4 | STOP | 指定通道；取消动作，先停止 PWM 后刹车，等待余转结束 |
| 5 | STOP_ALL | 四路停止；通道字段忽略 |
| 6 | BRAKE | 1 刹车并取消动作；0 仅释放，运动/故障中拒绝释放 |
| 7 | DIRECTION | 0 CW / 1 CCW，仅静止通道；不启动、不保存 |
| 8 | SAVE | 全静止后重试保存，清成功后的存储错误锁定 |
| 9 | CLEAR_FAULT | 全静止后清指定通道故障；不会恢复已经失效的零点 |
| 10 | SELFTEST | 指定通道 0～3；参数 0 逻辑正向、1 逻辑负向；无需有效零点 |
| 11 | SELFTEST_ALL | 按 M1→M4 检查全部物理通道，不要求启用/减速比/零点；无响应确认停止后继续，安全异常中止；通道字段忽略，参数同上 |
| 12 | MANUAL_ADJUST | 指定通道，参数1进入/0退出；条件和dirty生命周期见人工调整手册 |

MOVE 的实际 DIR 由“角度正负 XOR inverted”决定，会覆盖 DIRECTION 临时电平。要让机械正方向永久反过来，应在配置中修改 inverted，再重新设零；不要把 DIRECTION 当成 MOVE 的另一个方向参数。

状态：`0未就绪，1空闲，2运行，3减速，4等待余转结束，5到位，6故障，7自检试转，8人工调整`。

故障：`0无，1反馈超时，2动作总超时，3FG漏捕获，4静止意外脉冲，5位置越界/到位误差超限，7自检失败`。存储错误由板级 0006 单独报告；代码保留枚举 6 供后续扩展，本版不以该值替代板级存储标志。

自检状态（+20）：`0未检测/未执行，1等待，2试转，3等待停止，4通过，5失败，6取消，7跳过`。自检原因（+21）：`0无异常，1无脉冲，2脉冲不足，3捕获错误，4其他通道活动，5停止确认超时，6取消，7存储失败，8位置越界，9返回超时，10返回偏差超限`。状态 0 且请求序号/原因来自本批，表示因安全异常或取消中止而未执行。状态 7 保留兼容，当前批量不会跳过禁用通道。无脉冲/脉冲不足通道保持失败，确认停止后继续检查后续通道。

自检独占四路运动控制，正常运动可以四路并行的规则在此期间不适用。STOP、STOP_ALL、任一路 BRAKE=1 取消整批；读取不受影响。自检只表示最近一次 FG 响应情况，不等于物理插接检测或持续在线状态。完整互锁、停止超时恢复、位置与保存规则见[自检文档](Robot_电机自检.md)。

业务结果：`0成功，1值非法，2忙，3未就绪，4存储错误，5序号冲突/过旧，6地址非法`。Modbus 映射为：地址→异常 02；值/序号→03；忙→06；未就绪/存储→04；未知功能码→01。CAN 直接返回业务结果值。

“命令接受成功”“机械到位”“位置已保存”是三个阶段。运动后轮询对应通道状态、有效位以及板级 dirty/pending_save/storage_error；只有到位且有效、dirty=0、pending_save=0、storage_error=0 才是正常完成并保存。STOP/BRAKE 取消的动作不会报告到位。

### 请求重试规则

- 免序号操作填 0：每次调用分配新的非零编号，跳过零和缓存内编号；业务失败也分配。Modbus 命令快照中的请求序号仍为零，重复发送完整命令仍是新请求；CAN 应答回显零，实际编号从 0036 读取，自检 +27 保存启动实际编号。不绕过运动互锁，也不增加 Flash 写入时机；Flash image 仍为 136 字节、schema 1。重启不自动续跑。旧客户端把零当显式序号的行为不再兼容，需跳过零。
- 以下去重和重试约定仅针对非零模式。一个主站给一块板分配统一递增 uint16 序号，含失败请求。读 0036 后取下一号，65535 后跳过 0 使用 1；每次向前差值必须小于 32768。
- RAM 缓存最近 16 个命令的完整操作码、通道、参数和结果；相同序号/内容返回原结果，运动不重复。相同序号但不同内容被拒绝。缓存外的过旧序号也被拒绝。
- 起动前和动作完成保存均包含序号。重启后不恢复 RAM 缓存；已保存旧序号被拒绝，不能通过重放旧 MOVE 再转一次。
- 一个暂存配置的重新提交必须使用新序号；重试必须同时保持原暂存内容和原命令。更换了配置却复用旧提交号不会应用新配置。
- 通信超时不能推断“没执行”。先查询，必要时使用**原序号、原参数**重试。重启后重新建立会话、读取有效位和序号；不要重放历史队列。多主站、跨很长时间的 16 位回绕旧包不在本协议支持范围。

## 4. CAN 帧

CAN0 PD0 RX / PD1 TX，500 kbit/s，标准 11 位数据帧，DLC 必须等于 8。节点 1～127。请求 ID=`0600+node`，应答 ID=`0580+node`。扩展帧、远程帧、其他 ID、错误 DLC 被丢弃。CAN 收发器、端接、电平、是否共地仍需按实际板检查。

同样读写上一节寄存器。下表数字是每个字节内容；`AH/AL` 是寄存器地址，`VH/VL` 是 16 位值，所有多字节数高字节先发。

| 操作 | 请求 8 字节 | 应答 8 字节 |
|---|---|---|
| 读 1～2 个寄存器 | `01 tag AH AL count 00 00 00` | `81 tag result count V0H V0L V1H V1L` |
| 暂存单寄存器 | `02 tag AH AL 00 VH VL 00` | `82 tag result 00 00 00 00 00` |
| 直接执行命令 | `03 seqH seqL op ch argH argL 00` | `83 seqH result seqL 00 00 00 00` |

CAN 命令参数为 **有符号 int16**，足以表示 ±3600 和开关值；语义与 Modbus int32 相同。CAN 禁止通过写 0035 触发命令，统一用操作 03。读取 UID 分三次读 `0008/000A/000C`，每次两个寄存器。读取 int32 位置一次取两个寄存器，保持单值一致；多个 CAN 应答之间不是跨通道锁定快照。

请求逐次发送并等待匹配 tag/seq 的响应，禁止洪泛或并发暂存。发送采用非阻塞邮箱，50 ms 失败/超时后释放；主站应重试同一请求。驱动未启用无限自动重发；链路故障不会阻塞电机控制循环。

新板默认都是地址 1。先逐板经 CH340 配置不同 CAN node，保存并重启，再接入同一 CAN 总线；不能依靠重复节点号在线区分板。UID 用于身份绑定，node 用于寻址。

## 5. 上位机工具

[robot_host.py](../tools/robot_host.py)支持 pyserial 和 python-can 插件接口；本次只执行了离线测试和 `--help`，没有打开任何硬件连接。依赖按实际运输层安装：`pip install pyserial` 或 `pip install python-can`。某些 CAN 适配器还需其厂商驱动/附加依赖。

```powershell
# 先只读取实际板 UID 与状态；以下 COM4 是示例。
python tools/robot_host.py --port COM4 status

# 准备整机 JSON 清单，键改为实际完整 UID，并按真实关节填四路配置。
# 写操作必须 --uid；以下 UID 是占位示例，不能直接用于实际板。
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 config tools/robot_inventory.example.json

# 全机停止并处于指定机械参考姿态后，对 M1 手动设零。
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 zero 1

# M1 相对输出轴 +30°；M2/M3/M4 分别使用对应编号。
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 move 1 30
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 brake 1 1
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 direction 1 1
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 stop-all

# 先确认机械活动空间；批量无需配置，单路需启用/减速比；均不要求设零；正常去程停稳后按实际总脉冲反转返回。
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 selftest 1 --direction positive
python tools/robot_host.py --port COM4 --uid 12345678ABCDEF0198765432 selftest all --direction negative
python tools/robot_host.py --port COM4 status

# CAN 适配器示例；参数应依据实际驱动替换。
python tools/robot_host.py --transport can --interface slcan --can-channel COM5 --node 2 status
```

脚本输出请求 seq，重试不确定的动作时用 `--seq 原非零序号`，保持其余参数相同。脚本自动分配时回绕跳过零，拒绝 `--seq 0`，避免自动重试重复动作。连续重新运行不带 `--seq` 的 MOVE 是**新的相对动作**。示例清单的通道全部禁用、未分配；工具不猜测哪一关节应使用哪种减速比。

当前系统时钟沿用 120 MHz；APB1=60 MHz、APB2=120 MHz，定时器时钟按 APB 分频推导，不能直接把 TIMER1/2/3 当 60 MHz。TIMER1 中断处理 FG1/FG4，TIMER2 处理 FG3，TIMER0_Channel 处理 FG2，TIMER0_UP 负责溢出。捕获最高优先于串口；溢出扩展要求有效捕获期间中断延迟小于半个 16 位周期（32.768 ms）。电机运动时禁止 Flash 写入，以免其阻塞执行导致丢 FG。

业务状态只由主循环修改。中断更新原始计数/时间；主循环短暂屏蔽中断取四路反馈一致副本。自检额外使用 SysTick 在达到当前行程目标（去程三脉冲、返程为去程含余转总脉冲）、每程 2000 ms 或发现反馈异常时停止被测输出并留存快照；主循环先消费该快照，再处理余转，ISR 不保存 Flash、不执行协议或切换下一路。状态查询不在 ISR 中解析。正常运动主循环每 10 ms 调节 PWM，但每轮都检查计数越过目标；调节使用 RPM 前馈、比例项、受限积分和向上斜率限制。剩余 30°内减速到 400 RPM 下限，不自动反复反转修正超调。自检使用独立的 0～100‰ 爬升，绝不进入上述速度环。调参常量集中在 [robot.h](../BSP/robot.h)；这些值是初始软件参数。

无 FG 1 s 停机；单次动作总超时为 `10 s + 4 × 理论巡航行程时间`。静止判断为 500 ms 无边沿，不等价于具有绝对静止传感器。掉线动作按原目标继续。未实现软件关节总行程限位、碰撞检测、硬件限位、上位机心跳急停、负载静态保持保证。

PA15 按键急停仍默认关闭 `BUTTON_ESTOP_ENABLE=0`；用户此前说明未接按键。本版打开宏后的路径不再用延迟消抖。旧 motor_test 命令行、RS485/USART2 测试和 USB CDC 不进入当前主循环。

两套构建均增加五个 robot 源文件并使用同一保留区链接脚本；CMake 和独立构建清单移除 motor_test。EIDE 保留 USB 参考源码的编译项，主循环不初始化 USB。增加源码时同步 [CMakeLists.txt](../CMakeLists.txt)、[eide.yml](../.eide/eide.yml)、[build_verify.ps1](../tools/build_verify.ps1)；[build_eide.ps1](../tools/build_eide.ps1)读取 EIDE 清单。

## 7. 分阶段硬件验收（本次未执行）

1. 电机电源断开：确认上电、复位、故障、STOP 的 PWM 电机端持续高，BRAKE 低；确认同相转换、引脚和 25 kHz；测 FG 输入电压。
2. 卸载/机械防护下，先配置较低 RPM；检查每一路 CW/CCW、BRAKE、PWM 低时间比，确认通道没有串线。换向前必须停稳。
3. 用已知频率脉冲核对四路 FG：800 Hz 对应减速前 8000 RPM；覆盖第二路 TIMER0_Channel、低频跨 16 位溢出、停转测速归零、漏捕获标志。
4. 每种实际减速比，人工测量输出轴 ±30°、±90°、±360°和连续多圈累计；覆盖不同负载、正反向和四路同时运行。以独立角度测量判定 ±5°，不能仅看 FG 自己报告 DONE。
5. 校准减速距离、低速稳定区、积分和刹车惯性；检查同路忙拒绝、STOP/BRAKE 取消、释放不恢复、临时方向不启动、反相/换减速比后绝对参考失效，相对 MOVE 可执行且不自动恢复有效位。
6. 通信测试：CRC 错、截断、字节间长间隔、最大 ADU、重复 MOVE/序号冲突、掉线、CAN 无 ACK/总线关闭、节点冲突；操作不能重复或阻塞控制循环。
7. 保存测试：全部停止保存成功后断电恢复；运动途中断电必须使所有零点失效；在 dirty 写入、完成记录写入、页切换时分别中断电源。读回配置和 UID，不自动复动。
8. 验证主站整机标签唯一、替换板 UID 拒绝、两块板独立访问，以及实体急停/机械限位方案。带负载机械臂不能假设电机驱动的电子刹车等于失电保持制动器。

官方核对入口：[GD32F30x 用户手册 Rev2.9](https://www.gd32mcu.com/data/documents/userManual/GD32F30x_User_Manual_Rev2.9.pdf)（定时器捕获标志/存储器章节）、[GD32F30x 资料下载](https://www.gd32mcu.com/en/download/6?kw=GD32F30x)、[Modbus 串行指南](https://modbus.org/docs/Modbus_over_serial_line_V1_02.pdf)。8N1 是本工程按已确认方案选择的线路格式；若与其他要求奇偶校验或双停止位的 RTU 设备互联，须显式统一格式。
