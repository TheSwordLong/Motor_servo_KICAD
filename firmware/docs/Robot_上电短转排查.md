# 单片机上电时电机短暂转动：排查与保护调整

开始[多次角度报文测试](Robot_免序号操作.md#repeated-angle)前，仍需核对本页供电和停止电平问题。故障4按已生效减速比判断累计非预期活动>10°才触发，不代表已消除同时上电短转；连续 MOVE 的报文接受、完成、保存状态也不能代替电气波形和机械回位测量。本页既有用户观察保持原含义。

## 已观察到什么

用户报告“单片机通电时，电机会转一小段”，随后提供供电顺序对比：

- MCU 已上电运行时，单独给电机通断电：电机不会转。
- MCU 与电机同时上电：电机先转一小段。

用户进一步确认：已经烧录启动保护前移的新固件，仍会短转；PWM/BRAKE 直接连接电机，无中间电平转换。外部上下拉是否存在仍未回答，不能把“直连”当作“没有电阻”。

以上是用户报告的实体观察，助手没有操作硬件。它支持优先检查共同上电时 MCU 停止输出尚未建立的窗口及电源时序，但还不能确定故障控制线或唯一根因。尚未确认具体通道、通信是否断开及外部上下拉电路。提前到 SystemInit 之前的调整未消除用户复测中的短转，不能把它记录为故障已修复。此前 M2 的 state=6、fault=4 表示软件曾检测到非运动状态 FG 活动；可能与短转有关，但不能证明是同一次事件，也不能排除 FG 干扰。

官方 [GD32F30x 用户手册 Rev3.0](https://www.gd32mcu.com/data/documents/userManual/GD32F30x_User_Manual_Rev3.0.pdf) 的 GPIO 说明指出，复位期间/刚复位时普通 GPIO 为浮空输入，内部上下拉未启用。这解释了为何运行后的软件停止设置不能自动覆盖复位阶段；实际板上电机端电平仍需原理图或波形确认，不能把浮空直接等同于一定低电平。

## 当前启动保护代码事实

原启动路径：RAM 初始化 → SystemInit 等待晶振/PLL → C 构造函数 → main 中停止输出。main 之前没有主动设置电机停止电平；晶振初始化失败还有等待路径。不能把“没有发送运动命令”直接等同于“通电瞬间引脚始终处于停止电平”。

现有实现是在 [Reset_Handler](../startup/startup_gd32f30x_hd.S) 的 RAM 初始化后、SystemInit 前调用现有 `robot_emergency_stop()`，使四路 PWM 尽早输出高电平，BRAKE 尽早输出低电平。main 与故障处理原有调用保留。该函数及其调用链只使用整数 GPIO/RCU 寄存器操作，不依赖 SysTick、定时器或 FPU 已初始化。

正常 [PWM 初始化](../BSP/pwm.c)已经先输出高电平、设零占空比、启动定时器，再切换到复用输出；本次未改 PWM 极性、频率、通道、刹车逻辑或 Modbus/CAN 协议。另纠正 `motor_pins.h` 中“刹车上电默认释放”的过时注释，实际初始化为施加刹车。

**这只是缩短一个已确认的软件保护空档，不是已确认的短转根因或硬件修复结论。** 它不能覆盖 CPU 尚未离开复位、供电尚未建立或 RAM 初始化之前的阶段；实际电机端电平还受外部电路影响。

## 人工排查顺序（本次未执行）

先让机械处于可容许短暂运动、没有悬空负载的测试状态，不发送任何自检/MOVE/释放刹车命令。需要改接线时先断开动力电源。

| 步骤 | 操作 | 可以区分什么 |
|---|---|---|
| 1 | 关闭上位机自动发送；在不影响供电/共地的前提下断开通信信号后复测 | 若仍短转，通信命令不是必要触发条件；若消失，再查旧命令自动发送及通信连接对电路的影响 |
| 2 | 记录电机动力保持上电时，MCU 单独复位/上电是否短转 | 定位与 MCU 复位过程相关的情况；仍不能仅凭现象区分 GPIO、电平转换和供电问题 |
| 3 | 用户已报告 MCU 先启动时电机通断电不转，共同上电短转；下一步记录对应固件版本并复测 | 支持关注上电时序，但不是新固件修复有效或唯一根因已确认的证据 |
| 4 | 按正确目标产物下载本次固件，用相同接线、供电、负载条件复测 | 判断前移软件停止设置是否改善现象；保留修改前后记录 |
| 5 | 用示波器在电机接口处捕获 PWM、BRAKE 与 MCU 电源/复位时序，必要时再测 MCU 引脚侧 | 找出运行电平出现在哪一段，判断是否由转换电路改变了极性或上电电平 |

电机端按既有规格应为 PWM 高停止、低运行；BRAKE 低刹车、高释放。测量仪器输入范围、参考地与探头接法必须适合实际电路。没有原理图和波形前，不指定上拉电压、电阻值或把信号直接接到某电源。

若发现停止电平在复位期间不成立，需要结合原理图设计外部默认停止/刹车或使能保护；软件内部上下拉配置同样要等代码执行，不能代替 CPU 复位期间的硬件措施。若电机端控制电平一直正确仍有短转，应继续查电机驱动器自身上电行为、供电及负载运动，不能反复改 PWM 参数猜测。

启动后可只读检查四路状态和故障，报文见[免序号操作的查询表](Robot_免序号操作.md)。有 FG 活动故障时先保留记录，不清掉证据后宣称上电正常。
