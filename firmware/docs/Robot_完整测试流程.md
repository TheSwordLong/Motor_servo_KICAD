新增[多次角度报文测试](Robot_免序号操作.md#repeated-angle)：以 M2 连续 +20°、+20°、−20°、−20° 为例，给出 Modbus 完整命令直接执行/读取、CAN 执行/读取及逐次等待条件。该四次实体运动仍待执行；FG 阈值修改的实际构建和 11 组 C 回归结果见[FG 验证记录](Robot_FG调试观察.md)，下文早期构建尺寸/数量属于历史快照。

新增免序号模式后，手动执行帧请用[固定 0000 报文](Robot_免序号操作.md)。非零序号去重仍保留；零序号每次提交分配新编号，必须禁止盲目重试。最新增量结果见[验证记录](history/Robot_自检验证记录.md)，本页第 9 节保留增量前的重测快照。

本流程将软件回归、编译检查、报文检查和实体板验收分开。2026-09-25 本轮已完成软件测试及两套构建，结果见文末；**未烧录、未连接串口/CAN、未启动实体电机**。软件通过不能代替引脚电平、实际回位和负载测试。

实际发帧使用[完整 HEX 操作步骤](Robot_免序号操作.md)，其中已有 Modbus/CAN 的发送帧、应答和等待条件，不需要 Python 上位机。发生错误时使用[查询与恢复步骤](Robot_免序号操作.md#recovery-steps)。

## 1. 固定本轮测试对象

- 记录固件 ELF 哈希、板卡 UID、站号/节点号、四路接线、实际减速比、供电和负载条件。
- 保存现有四路配置与已知机械姿态。不要为了测试空白配置而擦除正在使用的板卡数据；空白配置路径已在软件模拟中覆盖，实体测试使用专用测试板。
- 构建不会更新板上的程序。下载后应使用同一产物继续验收；只读查询往返寄存器可以检查接口是否存在，但不能替代产物身份记录。
- 每个硬件项目记录 TX/RX、请求序号、状态/原因、实际测量值及通过/失败；遇到故障先保存记录，再恢复。

## 5. 实体板第一阶段：下载与静态电气检查（待执行）

1. 电机动力电源断开，确认板卡、SWD 和电源连接，选择本轮生成的固件。按[编译与下载操作手册](编译与下载操作手册.md)人工下载；保留末尾配置页，不做整片擦除。
2. 复位后测四路 PWM 为停止电平、BRAKE 为刹车电平。代码约定 PWM 高停止、低运行，BRAKE 低刹车；确认板上电路到电机端的实际有效电平一致。
3. 核对 M1～M4 固定引脚、DIR、FG，无通道串线。核对 FG 输入电平及信号质量；PA15 按键默认关闭，不能作为已接好的急停使用。
4. 用只读报文读取 UID、最近序号/结果、存储标志和四路状态。此阶段不提交运动、自检或释放刹车命令。

默认站号 01 的只读起始报文（HEX 发送，无 CR/LF，已含 CRC）：

| 查询 | TX |
|---|---|
| UID | `01 03 00 08 00 06 44 0A` |
| 最近序号/业务结果 | `01 03 00 36 00 02 24 05` |
| dirty / storage_error / pending_save | `01 03 00 05 00 03 15 CA` |
| M1 状态至 RPM | `01 03 01 10 00 07 04 31` |

通过标准：身份与目标板一致，报文正常应答，停止输出符合实测；无未处理存储错误或故障。无应答先查端口、115200/8N1、实际站号、HEX/CRC、共地与接线，不重复提交动作。

## 6. 实体板第二阶段：四路往返自检（待执行）

在机械有活动空间、可直接切断动力且无悬空负载的条件下进行。换接电机或制造 FG 断线场景前先断开动力，不带电插拔。自检每程最大 10%/2000 ms，不保证固定转角。

1. 四路全部停止并连续至少 500 ms 无 FG，先处理未清故障和存储错误。
2. 按免序号文档发送批量自检的“发送完整命令”，序号固定 0000；提交后读取实际分配序号并记录。若选择非零模式，使用有效新序号，旧文档的序号 16 不能永远照抄。
3. 轮询四路原结果和[新增往返字段](Robot_免序号操作.md#roundtrip-results)，不重复发送新启动命令。观察固定 M1→M4 顺序、同一时刻仅一路试转。
4. 正常通道应为：去程至少 3 FG → 刹车并统计余转 → 停稳 → 按去程总数 N 反转 → 刹车并统计余转 → 检查残差。换向前停止至少 500 ms，且四路连续 500 ms 无 FG。
5. 每路通过需状态=4、原因=0、阶段=5、请求序号匹配；残差仅记录；同时记录去程/返程脉冲、两程通电时间。批次结束还需全部停止、存储三标志全 0。
6. 独立测量真实轴位置是否返回。FG 单线不能识别真实方向，计数通过不能证明机械精确回位；不要把计数归零当成机械测量。

| 测试场景 | 应有行为 |
|---|---|
| 四路正常连接 | 逐路完成往返；无自动重复自检；机械方向与通道对应 |
| 空白配置或禁用通道，使用批量 op 11 | 仍扫描四路，不自动启用、配置减速比或设零 |
| 去程无脉冲/不足 3 个 | 当前路失败，原因 1/2；不返程，确认停止后继续下一路；不能据此直接诊断为“未接” |
| 返程未达目标 / 非零残差 | 未达目标超时仍为原因9并中止；达到目标后残差仅记录，不自动补转 |
| 其他通道非预期 FG / 捕获错误 | 有效减速比下累计活动≤10°不报警，>10°中止整批；516/290/82测试86/87、48/49、13/14边界，未配置不报故障4并使相应位置失效；捕获错误仍立即中止。静止间隔不清累计；重启、成功清故障或设零清零；本版每次超限事件、自动恢复及手动进入也重置活动累计。验证依据见 [FG 阈值](Robot_FG调试观察.md) |
| 任一行程或停稳阶段发 STOP、STOP_ALL、BRAKE=1 | 取消整批并停止，不再自动返回；被测位置失效 |
| 停止后 2 s 仍不能确认静止 | 停止超时锁定，不继续下一路或新运动 |

反馈错误、停止超时等危险场景优先用脉冲源/测试夹具验证；软件模拟已经覆盖，不能为了复现而强行堵转带负载机构。具体原因和恢复条件见[错误说明](Robot_Modbus与CAN使用手册.md#error-recovery)。

## 7. 实体板第三阶段：配置保存与角度控制（待执行）

1. **记录自检结果后再改配置**，因为相关配置变更会清 RAM 结果。依实际型号写四路 enabled、role、gear、inverted、目标 RPM；未安装通道保持禁用。
2. 按操作文档第 5 节暂存四路参数，一次 CONFIG 保存到板上；读回已应用配置和存储三标志。SAVE 不提交暂存配置，不需另发 SAVE 代替 CONFIG。
3. 停止并保存成功后断电重启，确认 UID、四路减速比等仍在；记录首次验证时断电期间轴未被外力转动。
4. 各通道在已知参考姿态手动 ZERO，检查 valid=1、角度=0、fault=0、保存完成。ZERO 不会驱动电机找零。
5. 按操作文档第 7 节先 M1 +20°，等 DONE、无故障、位置有效，再发 −20°；分别对 M2～M4 重复。发送的是输出轴角度，不再乘减速比。用独立角度测量检验 ±5°，不能只看固件自己的位置读数。
6. 从低速、空载开始，再分别验证实际 516/82/290 减速比、允许的正反角度、不同速度与负载。固定机构没有足够行程时，不执行 ±360° 或多圈；这些在拆离机构的测试台上验证。
7. 验证四路独立并行、同路忙拒绝、STOP/STOP_ALL、刹车取消、方向命令不自行启动、释放刹车不恢复旧动作。方向反相/减速比变化后检查位置失效；验证不设零也能相对 MOVE 且有效位保持 0，只有建立绝对参考才 ZERO。

方向正负以逻辑方向和 inverted 为准，先在单路实测确认。普通 MOVE 的 ±5°判据保持不变；自检残差仅显示，不据此失败。

### 7.1 连续四次 M2 角度操作（待执行）

1. 确认 M2 当前配置与实物一致、已启用、valid=1、无故障和存储错误，机械允许累计 +40°。记录当前参考位置，仅在需要建立参考姿态时 ZERO。
2. 按[完整帧](Robot_免序号操作.md#repeated-angle)发送第一次 +20° 完整命令直接执行。核对本次实际序号及结果 0，再轮询 DONE=5、fault=0、valid=1；读取实际角度/目标/计数和保存三标志。
3. 上一步完成且保存后，发送相同的 +20° 完整命令直接执行，重复读回。期间不设零、不重新 CONFIG，也不重复自检。
4. 分两次发送 −20°，每次都重复接受、完成、位置和保存检查。理想相对起点位置依次 +20°、+40°、+20°、0°；记录实际值，不把理想值填作实测。
5. 核对每次目标从当前实际计数生成，允许脉冲量化及余转影响；用独立测量检查单次运动误差和最终回位，不能仅靠正负参数相加认定已回零。
6. 在测试台另测同路运行中提交 MOVE，应返回忙且不排队；需要的下一次动作须停稳后重新明确发起。收到无应答时只查询，不用零序号重提交模拟通信重试。
每次操作发送完整命令。停止后要继续运动时重新发送 MOVE；不要重发结果未知的零序号运动命令。
8. 若使用 CAN，按同一入口的执行/查询帧重复上述步骤；记录请求 ID/响应 ID、tag 和实际执行序号，不发送 Modbus 提交帧。不同时开启两种协议。

## 8. 实体板第四阶段：协议、异常和掉电（待执行）

| 项目 | 操作及判据 |
|---|---|
| 序号去重 | 非零原序号、原内容重发已接受请求，确认不再次转动；结果未知先读状态，不能换号重试相对 MOVE |
| 免序号新请求 | 在测试台等前次 +20° 完成，再提交相同零序号命令，应作为新动作再转 +20°；忙时重复提交应拒绝。检查 0036 实际编号变化与自检 +27 归属，不把此操作当成通信重试 |
| 参数/序号/忙错误 | 分别发送越界参数、冲突序号和忙时命令，核对异常及最近结果；未接受动作不得启动 |
| 异常帧 | CRC 错、截断、字节间隔异常等，确认无误动作，恢复有效帧后可继续查询 |
| 通信断开 | 在测试台观察普通 MOVE 继续至目标或自身故障停止；本固件没有断联急停，不应期待拔串口即可停止 |
| CAN | 静止时保存切换配置后人工重启，使用 500 kbit/s、标准帧、DLC=8；node=1 时请求 ID=0x601、响应 ID=0x581。按操作文档第 10 节重复身份、自检、配置、设零、±20°及停止，比较两种协议业务结果 |
| CAN 异常 | 在测试网络检查无 ACK、节点冲突和总线异常，记录是否恢复；不能影响停止保护；CAN 与 Modbus 不是同时工作 |
| 正常保存后掉电 | 重启读回配置和位置，确认不自动运动；位置恢复的前提是断电期间轴未转动 |
| 运动/自检中掉电 | 在专用测试台切断动力，重启应使 dirty 对应位置无效，不续跑、不自动返程；核对后重新手动设零 |
| Flash 故障 | 断写/页切换的 129 种注入已在模拟中测试；实体随机断电是补充，不能宣称覆盖同样 129 个精确时点 |

遇到 `01 90 04 4D C3`：先读最近序号/业务结果，再读存储标志和通道故障。异常 04 本身不能区分“未就绪”和“存储失败”。恢复后需重新检查下一命令的前置条件；清故障不等于恢复有效零点或修好 Flash。

## 无零点相对运动验收（2026-09-29）

烧录本次构建后，使用独立测角与允许试转的测试台验证：正确配置但从未 ZERO 的通道可接受相对 MOVE；正常完成应 DONE、fault=0、刹车=1、PWM/转速=0，而 valid 仍为 0；保存并重启后仍为 0。正负各测一次，并对照运动前后 FG 差，不将保留计数解释成绝对角度。

通过主机模拟注入故障时，不清故障的 MOVE 应拒绝；显式清故障后不发送 ZERO 即可执行相对 MOVE。故障再次发生应立即停止测试，不能自动清除重试。使用安全测试台单独验证 dirty 恢复不续跑、新请求允许相对运动且不恢复零点；反馈异常、存储错误、停止输入、停止超时锁仍阻止或终止运动。Modbus 与 CAN 都需验证；报文见[恢复步骤](Robot_Modbus与CAN使用手册.md#unreferenced-relative)。硬件验收尚未执行。
