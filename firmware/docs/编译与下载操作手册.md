# 编译、下载与VS Code调试手册

下载对应固件后，手动发帧可直接使用[连续多次相对转角的 Modbus/CAN 步骤](Robot_免序号操作.md#repeated-angle)。每次先确认接受再等运动完成和保存，不用每次重编译、重下载、重配减速比或设零。仅更新本文等 Markdown 不会更新板上固件；本次文档同步未执行构建、下载或硬件动作。当前 FG 阈值固件的既有构建结果见 [FG 验证记录](Robot_FG调试观察.md)。

当前已实现往返自检：去程采集含余转脉冲 N，停稳后反向以 N 为目标返回，最终残差仅记录，不作为通过判据；两程各限 10%/2000 ms。新增阶段和回位结果见[往返结果寄存器](Robot_电机自检.md#roundtrip-results)。换向仍由主循环在静止确认后执行，中断只截止当前行程输出。旧单向版本验证记录仅供历史追溯。

首次装机按[四路检测 → 减速比配置 → 板上保存 → 读回 → 设零](Robot_Modbus与CAN使用手册.md#commissioning)进行。批量检测无需配置，角度控制才需要有效配置和零点。四路减速比经 CONFIG 保存到驱动板末尾 Flash 日志区，上位机按 UID 备份；不需再发 SAVE 保存减速比。

CONFIG 成功后读回四路已应用值及存储标志，后续人工重启再核对保留情况。普通重新下载不应要求重填减速比，前提是日志区未擦除且格式兼容；不要为此整片擦除。换板必须重新核对 UID 和实际硬件。硬件持久化核对尚未执行。

适用当前四路机器人电机固件。通信控制见 [Modbus 与 CAN 使用手册](Robot_Modbus与CAN使用手册.md)，本文只说明构建、产物选择、下载和检查。以下硬件命令需由使用者按实际条件执行，本次文档清理没有烧录或运行电机。

## 1. 构建入口

在工程根目录运行，两种方式任选其一：

```powershell
# CMake / Ninja
cmake --preset debug
cmake --build --preset debug

# 使用 EIDE 源文件清单的独立脚本
powershell -ExecutionPolicy Bypass -File tools/build_eide.ps1
```

| 方式 | 产物目录 | 配置来源 |
|---|---|---|
| CMake | `build/debug/` | [CMakeLists.txt](../CMakeLists.txt)、[CMakePresets.json](../CMakePresets.json) |
| EIDE 脚本 | `build-eide/Debug/` | [.eide/eide.yml](../.eide/eide.yml)、[build_eide.ps1](../tools/build_eide.ps1) |

VS Code 默认 `Ctrl+Shift+B` 为 **EIDE Build Debug**；若用 CMake，请明确选择 **CMake Build Debug**。实际任务见 [tasks.json](../.vscode/tasks.json)。

以命令退出码 0、无编译/链接错误及目标产物存在判断成功；仅看到“Linking”并不代表后续步骤成功。`ninja: no work to do.` 表示无需重建，产物时间戳不变是正常情况。

```powershell
Get-ChildItem build/debug/GD32F303VET6_MotorControl.* |
    Select-Object Name, Length, LastWriteTime
Get-ChildItem build-eide/Debug/GD32F303VET6_MotorControl.* |
    Select-Object Name, Length, LastWriteTime
```

对应目录应有 `.elf/.hex/.bin/.map`，下载时选择本次实际构建的那一套。若构建停滞，先查看当前任务输出并停止该工程的构建任务，再重新配置；不要直接结束所有工程的 CMake/Ninja 进程。需要绕开 CMake 时可使用 EIDE 独立脚本。

## 2. 新增文件与存储布局

新增业务源码须同步 [CMakeLists.txt](../CMakeLists.txt)、[eide.yml](../.eide/eide.yml) 和 [build_verify.ps1](../tools/build_verify.ps1) 的显式清单，并核对各入口的 include/编译选项。BSP 不是 CMake 自动扫描目录；当前 GLOB 只用于标准外设库源目录。

目标宏 `GD32F30X_HD`，Cortex-M4、Thumb、`fpv4-sp-d16`、hard float。链接脚本 [gd32f303xE_flash.ld](../linker/gd32f303xE_flash.ld) 配置：

| 区域 | 当前布局 |
|---|---|
| 程序 Flash | `0x08000000` 起 508 KiB |
| 配置/位置日志 | `0x0807F000～0x0807FFFF`，两个 2 KiB 页 |
| RAM | `0x20000000` 起 64 KiB |
| 默认堆/栈预留 | 1 KiB / 4 KiB |

不能将程序区恢复为全部 512 KiB，也不要用整片擦除覆盖配置/位置日志。升级应保持存储格式兼容。具体保存规则见[固件协议](Robot_固件协议与验收.md)。

## 3. 离线测试

```powershell
powershell -ExecutionPolicy Bypass -File tools/test_robot.ps1
python -m unittest discover -s tests -p test_robot_host.py -v
```

C 测试默认使用工作区 `build/test-tools/ziglang/zig.exe`；也可按脚本参数指定主机编译器。这些测试替换硬件回调，不打开串口/CAN、不驱动电机。已有构建、测试、警告和哈希见[自检版本验证记录](history/Robot_自检验证记录.md)，不是本次文档清理重新测试的结果。

## 4. 下载

使用 CMSIS-DAP / SWD，核对 SWDIO=PA13、SWCLK=PA14、公共地、目标供电和 VTref；VTref 不等于向整板供电。下载会写 Flash 并可能复位运行，先确认电机和机械条件。

以下两条是替代选项，不需要连续执行：

```powershell
# 下载 EIDE 产物，脚本默认路径为 build-eide/Debug。
powershell -ExecutionPolicy Bypass -File tools/flash_openocd.ps1

# 下载 CMake 产物，路径为 build/debug。
powershell -ExecutionPolicy Bypass -File tools/flash_openocd.ps1 -UseCmake
```

[下载脚本](../tools/flash_openocd.ps1)还可通过 `-Firmware` 指定文件；默认依赖本机 `E:/DevTools/OpenOCD/`，换电脑需核对路径。先检查构建成功、ELF 路径及版本，再执行下载；以 OpenOCD 的编程/校验结果和退出码判断，不将命令已打印等同于执行成功。

连接探测选项 `-Probe` 不写 Flash，但会执行 `reset halt`，会复位并暂停芯片，不是对运动无影响的读取。

## 5. 下载后检查

| 检查项 | 当前固件预期 |
|---|---|
| 初始化后的 PWM | 0‰，电机端高电平停止；不会上电自动输出 25 kHz 试转方波 |
| 初始化后的 BRAKE | 低电平施加刹车；DIR/BRAKE 电平转换仍须按实际板核对 |
| 默认通信 | USART0 PA9/PA10，Modbus RTU，115200 8N1，无 ASCII 帮助或回显 |
| 已保存为 CAN | 人工重启后使用 CAN，500 kbit/s；与 Modbus 二选一 |
| 空白配置 | 四路禁用、减速比未配置、位置无效；先批量检测，再配置并保存、读回核对、手动设零 |
| 电机响应自检 | 仅收到有效上位机命令才试转，不自动执行 |
| PA15 按键 | 默认 `BUTTON_ESTOP_ENABLE=0`，不能按“按键已启用”验收 |

先用[使用手册](Robot_Modbus与CAN使用手册.md)中的只读请求确认 UID、配置、有效位和存储状态，再按[硬件验收](Robot_固件协议与验收.md#hardware-acceptance)进行输出和运动测试。不能以 FG 自报 DONE 代替独立机械角度测量。

首次装机按[检测→配置→板上保存流程](Robot_Modbus与CAN使用手册.md#commissioning)执行。四路减速比通过 CONFIG 保存到驱动板末尾 Flash 日志区；上位机按 UID 保存配置备份，不代替板上保存。CONFIG 成功后读回四路已应用配置及存储状态；后续人工断电重启再核对保留情况。普通重新下载不应要求重新填写减速比，前提是日志区未擦除且存储格式兼容。不要为此整片擦除；更换板子需重新核对 UID 绑定及硬件。

当前入口没有旧 USB/USART2/CAN 测试模式选择宏；不要用旧测试 main 替换 [main.c](../Core/Src/main.c)。调试任务和变量见 [VS Code 指南](编译与下载操作手册.md#vscode-debug)。

## 6. 常见问题

| 现象 | 检查方法 |
|---|---|
| 找不到编译器/Ninja | 核对 preset、工具链文件和本机路径，不以其他电脑的目录为准 |
| 下载找不到 ELF | 确认构建方式与下载目录一致；检查实际构建退出码 |
| F5 找不到 build 任务 | EIDE 调试配置的 preLaunchTask 当前是 `build`，需核对扩展是否提供；详见 VS Code 指南 |
| 无上电串口文本 | 当前是二进制请求/应答固件，无上电帮助属于正常行为 |
| 配置后不能 MOVE | 检查通道启用、减速比、故障和存储锁；固件相对运动不要求有效零点，不是重新烧录即可解决 |
| 停在断点后反馈异常 | 暂停会影响捕获和控制；调试暂停不能代替停止/刹车 |

未执行：本次文档清理没有重新构建、烧录、探测 SWD 或打开串口/CAN。

## 7. VS Code任务、Live Watch和寄存器工具

### VS Code 1. 配置文件与工具

| 文件 | 用途 |
|---|---|
| [settings.json](../.vscode/settings.json) | 工作区工具与编辑器设置 |
| [tasks.json](../.vscode/tasks.json) | EIDE/CMake 构建、下载、寄存器任务 |
| [launch.json](../.vscode/launch.json) | Cortex-Debug / OpenOCD / GDB 配置 |
| [CMakePresets.json](../CMakePresets.json) | Ninja 路径、debug preset 和输出目录 |
| [arm-none-eabi.cmake](../cmake/arm-none-eabi.cmake) | ARM 交叉编译器路径 |
| [eide.yml](../.eide/eide.yml) | EIDE 源文件清单与构建配置 |

当前文件引用 Arm GNU Toolchain `15.3.rel1`（位于 `E:/DevTools/`）、OpenOCD `E:/DevTools/OpenOCD/`、CMake `C:/Program Files/CMake/`，Ninja 路径在 preset 中含本机用户目录。换电脑需分别核对，不能仅修改系统 PATH 就假定所有绝对路径已同步。

EIDE 任务需要对应 EIDE 扩展；CMake Tools、C/C++、Cortex-Debug 和 MCU Peripheral Viewer 分别用于 CMake 管理、编辑、调试和 SVD 显示。这是现有工作流的组成说明，不代表本次已检查插件版本或重新安装工具。

### VS Code 2. 实际任务与快捷键

| 操作 | 当前配置/影响 |
|---|---|
| Ctrl+Shift+B | 默认 `EIDE Build Debug`，产物在 `build-eide/Debug/` |
| 运行 `CMake Build Debug` | 依赖 `CMake Configure Debug`，产物在 `build/debug/` |
| 运行 `EIDE Flash Debug` | 依赖 EIDE 构建，通过 OpenOCD 下载 EIDE ELF 并复位 |
| F5 | 按所选调试配置启动；launch 可下载/复位/暂停，不能只按快捷键判断行为 |
| Attach 配置 | 不主动下载，但连接/暂停仍可能影响固件时序 |

不要混用一套构建的 ELF 与另一套已烧录固件来观察变量。源文件改动后先构建，再根据目标板上的实际版本选择符号文件。

### VS Code 3. 调试配置与已知差异

| launch.json 名称 | ELF 路径 | preLaunchTask |
|---|---|---|
| `GD32F303VET6 (EIDE)` | `build-eide/Debug/GD32F303VET6_MotorControl.elf` | `build` |
| `GD32F303VET6 (CMake)` | `build/debug/GD32F303VET6_MotorControl.elf` | `CMake Build Debug` |
| `GD32F303VET6 Attach (查看寄存器/不烧录)` | EIDE ELF | 未指定 |

当前 tasks.json 显式定义的是 `EIDE Build Debug` 等任务，没有名为 `build` 的普通任务。EIDE 扩展是否动态提供该任务，需要在实际 VS Code 环境确认。因此不能保证 EIDE 配置按 F5 必然先构建成功。若报找不到任务，应核对并选择实际构建任务，或使用 CMake 调试配置；本次只更新文档，没有更改 launch.json。

文件还保留一个未填写程序路径的通用 `(gdb) 启动` 示例，它不是本 MCU 工程可直接使用的调试入口。

当前 Cortex-Debug 配置的 Live Watch 为 enabled=true、4 次/秒。运动和反馈测量不能假定调试读取没有时序影响；断点、单步或暂停时，PWM 外设可能保持最后输出，软件控制和停机时基无法正常推进。先使电机处于已确认的停止条件再调试。

### VS Code 4. 当前业务入口和观察变量

[main.c](../Core/Src/main.c) 依次执行 `robot_emergency_stop()`、`systick_config()`、`robot_port_init()`，随后循环 `robot_port_update()`。不要用空循环、counter 演示或旧 USB 测试 main 替换它；这些例子不包含当前输出停止与自检保护路径。

| 观察变量 | 含义 |
|---|---|
| `sys_tick_ms` | uint32 毫秒计数，自然回绕 |
| `g_robot.config` / `g_robot.staged` | 已保存/应用配置与暂存配置 |
| `g_robot.motor[0..3].state` / `.fault` / `.valid` | 四路状态、故障与位置有效位 |
| `g_robot.motor[0..3].position` / `.target` | 有符号 FG 位置/目标计数，不是角度数值 |
| `g_robot.motor[0..3].duty` / `.brake` / `.direction` | 低电平占空比‰、刹车逻辑与实际 DIR 逻辑 |
| `g_robot.motor[0..3].rpm` | 业务快照中的减速前 RPM |
| `g_robot.selftest[0..3]` / `g_robot.probe` | 最近自检结果与独占会话 |
| `g_robot.dirty` / `.pending_save` / `.storage_error` | 保存阶段与存储错误 |
| `g_fg[0..3].pulse_count` / `.errors` / `.last_edge_ms` | ISR 更新的反馈诊断值 |

暂停时看见的字段不是独立实测数据。应用应通过正常协议读取状态，不应在调试器中随意改 position、valid 或直接调用输出函数绕过互锁。

### VS Code 5. SVD 与寄存器工具

现有 SVD 为 [GD32F30x_HD.svd](../Debug/SVD/GD32F30x_HD.svd)，配置在 launch.json 的 svdFile。它只用于解释寄存器，不参与编译和固件运行，也不证明实际接线。

`EIDE Read Registers` 和 `EIDE Watch Registers (live)` 使用 [openocd_regs.cfg](../tools/openocd_regs.cfg) / [openocd_regs.ps1](../tools/openocd_regs.ps1)。这些旧工具会 halt/read/resume，当前清单中 USART0 和 TIMER3 的地址还与本地头文件不一致：

| 外设 | 旧脚本读取起址 | 当前头文件基址 |
|---|---|---|
| USART0 | `0x4000F400` | `0x40013800` |
| TIMER3 | `0x40000400` | `0x40000800` |

不能将该旧清单的输出作为 PWM/串口配置正确的证据；使用前需另行修正并核验。直接读取 USART DATA 等寄存器也可能影响接收状态。本次不修改或执行这些工具。

### VS Code 6. 开发时必须保留的约束

- 链接程序区为 508 KiB，最后 4 KiB 是配置与位置日志；RAM 为 64 KiB，默认堆/栈为 1/4 KiB，见[链接脚本](../linker/gd32f303xE_flash.ld)。
- 保留电机固定引脚、唯一 ISR 入口、FG 快照和主循环控制权。自检中断只截止输出、留存快照，不在 ISR 写 Flash。
- 当前 USART0 是二进制 Modbus，不能把 printf 日志混入同一端口。调试变量不需要恢复旧文本回显。
- RS-485、USART2、USB 不进入当前业务主循环；不要仅因为源码或旧宏存在就假定功能启用。USB 参考状态见[库说明](../Drivers/USB_Device/README.md)。
- 新源码同步 CMake/EIDE/独立脚本清单；构建、主机模拟、烧录和机械验收分别记录，不能相互替代。
