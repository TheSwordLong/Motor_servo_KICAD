# 四路电机响应自检

自检后进行多次角度运动时，使用[连续相对 MOVE 的 Modbus/CAN 步骤](Robot_免序号操作.md#repeated-angle)。自检通过不会为无效位置自动设零；先确认配置、有效零点、无故障及保存完成。普通 MOVE 完成状态是 5，自检通过状态是 4，不能混用。普通 MOVE 不自动返回，不需要每次 MOVE 前重新自检或 ZERO；自检往返与手动连续正负转角是不同功能。

只发送一次完整命令：功能码 10、起址 0030、数量 5；收到正常应答表示接受。不要再发送旧提交帧。

遇到自检拒绝、返程失败或存储异常时，按[查询及恢复报文步骤](Robot_免序号操作.md#recovery-steps)操作；各原因的具体排查与恢复条件见[完整错误说明](Robot_Modbus与CAN使用手册.md#error-recovery)。不要只清故障或改写零点就宣称已经返回起点。

首次使用顺序：读取 UID → 四路批量检测 → 记录结果并处理异常 → 配置四路减速比 → CONFIG 保存到驱动板 → 读回核对 → 手动设零 → 角度控制。详见[首次使用与保存职责](Robot_Modbus与CAN使用手册.md#commissioning)。

减速比按实际规格填写，FG 自检不能识别。驱动板 Flash 持久保存并执行换算，上位机按 UID 备份；不必每次开机重新配置。等待整批结束且全部静止后再提交 CONFIG，保存成功无需额外 SAVE。未使用通道保持禁用，已有故障仍需排查处理。此流程不是新增的固件强制门槛。

CONFIG 修改启用、标签、减速比或反相会清除对应 RAM 自检结果，重启也清空结果；需要留档时上位机须在提交前记录。减速比、标签或反相变化使位置失效，恢复绝对参考才需在已知姿态设零，相对运动无需 ZERO。保存配置、保存位置与保存检测历史是不同职责。

后续人工验收增加：空白配置完成四路扫描后填写实际减速比，CONFIG 后读回并在安全停止、保存完成后重启核对；未使用通道保持禁用，自检结果重置不能解释为掉线。此硬件验收尚未执行。

本功能由上位机手动触发，支持 Modbus RTU 和 CAN。上电不试转，不自动重试；正常去程完成并停稳后反转，按实际去程含余转脉冲返回。串口显示时间戳不在本次修改范围内。

原寄存器、操作码 1～9 和 Flash schema 1 保持不变。四路引脚和定时器映射不变，详见[固件协议与验收](Robot_固件协议与验收.md)。实现入口：[robot.c](../BSP/robot.c)、[robot.h](../BSP/robot.h)、[robot_port.c](../BSP/robot_port.c)。

## 1. 结果的含义

首次使用顺序：**四路批量检测 → 记录结果并处理异常 → 配置四路减速比 → CONFIG 保存到驱动板 → 读回核对 → 手动设零 → 角度控制**。先读取 UID 并确认目标板，完整通信流程见[首次使用与保存职责](Robot_Modbus与CAN使用手册.md#commissioning)。

减速比由人工依据实际规格选择，FG 自检不能自动识别。板上 Flash 持久保存并用于换算，上位机仅负责编辑、按 UID 备份和核对；无需每次开机重新配置。必须等整批结束且全部静止再提交 CONFIG，保存失败不能算配置完成；不需要另发 SAVE 来保存减速比。自检无响应的未使用通道保持禁用，已有故障仍需排查处理。

CONFIG 修改启用、标签、减速比或反相会清除对应 RAM 自检结果，重启也清空结果；若需要历史检测记录，上位机须在提交前自行记录。检测后配置是推荐操作顺序，当前固件不强制自检通过才允许配置。保存位置与保存自检结果不能混为一谈。

现有硬件只有 FG，无独立插接检测。通过表示去程窗口内至少三个 FG、返程在时限内达到实际去程总脉冲目标，两程未触发保护且已停稳；计数残差仅供诊断；无响应可能由未连接、未供电、堵转、驱动异常或 FG 断线造成，不能据此直接报告“电机未连接”。通过也不是持续在线状态或机械运动方向已验证的证明。

10% 指 PWM 低电平时间比例，不是额定转速的 10%，也不是固定转角。FG 断线时不能保证实际转角上限。首次检查须留出机械活动空间；不能假定电子刹车可以保持带重力负载的机械臂。

## 2. 执行过程与互锁

1. 四路全部停止且连续至少 500 ms 无 FG，无未处理故障或存储错误。单路自检要求该路已启用、配置有效减速比；批量自检不要求启用、减速比或关节标签。两者均无需设零。
2. 单路只测试指定通道；批量固定按 M1→M4 检查全部物理通道，包含禁用和未配置通道，不自动修改配置。禁用不代表批量自检时不会试转。
3. 先保存当前请求序号和 dirty=1，写入成功后才释放被测刹车。即使原本 dirty=1 也重新保存本次序号。其他通道保持刹车。
4. 使用独立自检逻辑：从 0‰ 开始，每 10 ms 增加 10‰，上限 100‰。主循环晚到时一次只增加一级，不补发跳级。不会使用普通 MOVE 的速度 PI、8000 RPM 目标或到位控制。
5. 窗口内至少三个 FG 上升沿且无捕获错误，即停止 PWM、刹车。释放刹车后 2000 ms 到期仍为零脉冲，则失败/无脉冲；一至二个则失败/脉冲不足。到期后的余转脉冲不会把失败改判为通过。
6. 停止后继续计数。至少经过 500 ms 且四路连续 500 ms 无 FG 才结束该路。两秒后仍不能确认静止，报告停止超时，保持输出停止和整批互锁，不进入下一路。
7. 去程满足三脉冲且停稳后，反向以去程含余转总脉冲 N 为目标重新从 0 爬升，每程最大 10%/2000 ms。达到目标立即刹车并统计余转；最终残差仅记录，不因其大小判失败。返程未达目标超时仍中止整批，残差大小不再中止整批，不来回补转。
8. 批量中的去程无脉冲/脉冲不足记为该路失败，不尝试返回，确认停止后继续下一路；返程失败、捕获错误、其他通道活动、位置越界、停止超时或取消中止整批，后续等待通道标记未执行。不会自动增加力度、反向复测或重试。整个批次结束并全部停止后统一保存一次，存储失败维持锁定。

未配置减速比时仍累计有符号 FG 计数用于诊断，角度寄存器返回 0 不代表真实角度为零；位置有效位保持 0。批量通过不会自动启用通道或设零。无响应通道保留自检失败故障，本批可以继续；下一次检测前仍需排查并逐路清故障，不自动清除历史故障。

试转方向参数 0=逻辑正向、1=逻辑负向，实际 DIR 为该参数 XOR 通道 inverted。单线 FG 无法独立核验真实转向；试转与余转都按命令方向计入位置。

整个批次期间拒绝 MOVE、DIRECTION、BRAKE=0、ZERO、CONFIG、SAVE、CLEAR_FAULT 及新的自检；允许读取和配置暂存写入；完整执行命令立即检查互锁。任一路 STOP、STOP_ALL、BRAKE=1 取消整批。按键急停仍默认关闭；打开 `BUTTON_ESTOP_ENABLE` 后也走统一取消入口，按住时禁止新运动/释放刹车，但继续处理状态查询。

停止超时时，+20 仍为等待停止，+21 为 5；直到静止确认通过后才转为失败。此后即使修改配置清除了结果，整板运动锁仍保留，须在静止时对故障通道 CLEAR_FAULT；清故障不会恢复位置有效位。ZERO 仅可在已知机械参考姿态下使用，也会清除该路故障。仍有存储错误时还需 SAVE 成功。

### 中断停机保护

其他通道FG按已生效减速比判断累计非预期活动：≤10°容忍，>10°停机并中止；516/290/82对应第87/49/14个脉冲。未配置有效减速比不因FG活动触发故障4，捕获错误仍保护。主循环与下述中断使用相同阈值，累计跨自检往返/通道切换保留。重启、成功清故障或设零清零；本版每次超限事件、自动恢复及手动进入也重置活动累计；捕获错误仍立即停机，静止确认仍要求 500 ms 无 FG。完整规则及本次验证见 [FG 故障阈值说明](Robot_FG调试观察.md)。

[systick.c](../Core/Src/systick.c) 每毫秒调用 `robot_selftest_safety_tick()`。该保护在当前行程目标脉冲（去程 3、返程为去程含余转总数）、反馈异常、其他通道活动或当前行程 2000 ms 到期时停止被测 PWM 并刹车，记录截止时反馈快照。即使主循环暂时没有轮询也不会继续主动爬升输出。主循环原子选择截止快照，先结算试转，再在后续轮次处理余转，避免把截止之后的脉冲用于判定通过。

ISR 不解析命令、不写 Flash、不切换通道。GPIO 输出与保护启停通过短暂屏蔽中断串行化。实际停止时刻、脉冲响应延迟和低有效电平尚未上板测量；2000 ms 是毫秒时基下的软件窗口，仍受时钟误差及中断延迟影响，不能据主机模拟声称硬件时序已经验收。

## 3. 位置与存储

- 原本位置有效且自检通过、计数可信：保留零点，去程及返程含余转全部按实际方向计数；尝试回到起点，位置不强制改写为原值。
- 原本位置无效：通过后仍无效；可执行满足互锁的相对 MOVE，恢复绝对参考才需手动设零。
- 被测通道失败或主动取消：位置失效，计数保留供诊断；未试转的正常通道不受影响。启动前 dirty 写入失败时尚未释放刹车，因此保留原位置有效性。
- 其他通道在已生效减速比下累计非预期活动超过10°：中止被测通道，同时使该异常通道位置失效。对应结果记录异常原因以识别来源；≤10°不因此报警或改变位置有效性，但仍延后静止确认。这些脉冲无可验证方向，不作为可信有符号位置累加。
- 试转、余转、切换下一路期间不写 Flash；整个会话纳入 `robot_is_busy()` 和底层保存保护。
- 最后保存失败：保持 dirty、pending_save 和 storage_error 锁定，不自动重试写入。静止后通过 SAVE 显式重试。自检通过但保存失败时，状态仍为通过、原因为存储失败；已有更早异常原因时保留该原因，另查板级存储错误。
- 保存成功需同时满足 `0005 dirty=0`、`0006 storage_error=0`、`0007 pending_save=0`。通过只说明响应，不能代替这些标志。
- 自检途中掉电：恢复原有 dirty 规则，四路位置无效，不续跑、不恢复自检结果。保存后断电恢复位置的前提仍是断电期间轴不能被外力转动。

自检结果只在 RAM，重启为未检测。成功提交启用、关节标签、减速比或 inverted 变化会清除对应结果；只改 RPM 不清除，提交失败也不清除。

## 4. 命令和结果寄存器

新增操作码 **10 单路、11 批量**；参数只允许 0/1。单路通道字段 0～3，批量忽略该字段。沿用完整命令直接执行；非零序号同号同内容去重，0000 则每次分配新编号。命令应答表示接受，最终结果必须轮询。自动模式启动后读 0036 记录本批实际编号，+27 与它核对；不得与发送的零比较。不确定时先查询，不盲目重新提交。

每路固定基址：M1=0100、M2=0140、M3=0180、M4=01C0，以下为十六进制偏移，全部只读。

| 偏移 | 内容 |
|---|---|
| +20 | 状态：0 未检测/未执行，1 等待，2 试转，3 等待停止，4 通过，5 失败，6 取消，7 跳过 |
| +21 | 原因：0 无异常，1 无脉冲，2 脉冲不足，3 捕获错误，4 其他通道活动，5 停止超时，6 取消，7 存储失败，8 位置越界，9 返回超时，10 历史返回偏差超限（保留编号，新版不产生） |
| +22～+23 | 往返 FG 总数含两程余转，uint32，高字在前 |
| +24 | 去程释放刹车至停止的实际毫秒数，uint16；去程停止时确定，包括最初 0% 阶段 |
| +25～+26 | 完成时系统运行毫秒数，uint32，高字在前，按 2^32 回绕，不是日历时间 |
| +27 | 对应请求序号，uint16 |

批量未执行通道为状态 0，保留本次请求序号和中止原因；与上电初始记录结合请求序号/原因区分。状态 7 只保留兼容，当前批量不会跳过禁用通道。未执行或启动前存储失败的完成时刻表示作出该决定的时间，没有通电。正在执行时完成时刻为 0；余转及停止超时尚未静止时也不声称已经完成。

原每路 +10 状态新增 7=自检试转；+11 故障新增 7=自检失败，具体原因读 +21。取消不凭空增加故障码，但会使该路位置失效。原 +18/+1A 的角度与有符号计数继续反映自检位移，+1C 仍是原 MOVE 目标，不作为自检返回目标。

CAN 使用同一寄存器和命令语义，每次读最多两个寄存器；多次 CAN 读取之间不是原子快照，查询中可先后复核状态和请求序号，终态读取更稳定。

## 5. 上位机工具

先读实际 UID、配置及状态。`selftest all` 可在空白配置下检测全部四路；单路自检才需要按真实接线配置启用和减速比。以下 COM8 是示例；把 `实际24位UID` 替换成 `status` 读到的完整值，脚本不会接受该中文占位符作为匹配 UID。

```powershell
python tools/robot_host.py --port COM8 status
python tools/robot_host.py --port COM8 --uid 实际24位UID selftest 1
python tools/robot_host.py --port COM8 --uid 实际24位UID selftest all --direction positive
python tools/robot_host.py --port COM8 --uid 实际24位UID selftest 4 --direction negative
python tools/robot_host.py --port COM8 status
python tools/robot_host.py --port COM8 --uid 实际24位UID stop-all
```

`selftest` 默认 positive。`status` 每路新增 `last_selftest`，包含数字值、英文状态/原因、总脉冲、通电毫秒、完成运行时间、请求序号。没有连接到实体串口或 CAN 的离线测试不会打开这些端口。

CAN 同样可用，例如：

```powershell
python tools/robot_host.py --transport can --interface slcan --can-channel COM5 --node 2 --uid 实际24位UID selftest all
```

首次失败后先排查供电、接线、负载及 FG，再静止清故障或重新设零，之后发送新自检请求。没有可远程提高试转力度或延长通电时间的寄存器。

## 6. Modbus 自检完整 HEX 报文（启动、查询）

分步发送说明及正反向示例见[通信手册：Modbus 自检完整报文](Robot_Modbus与CAN使用手册.md#modbus-selftest)。下方每一行都是独立请求，必须逐条发送。

默认站号 01，115200 8N1，十六进制发送，不附 CR/LF。逐条等待应答，不一次连发多个请求。帧中已含 CRC（低字节在前）。下面启动帧会实际释放刹车并试转。

先读最近请求序号和结果：

```text
01 03 00 36 00 02 24 05
```

下例假设下一有效序号分别为 1 和 2。**实际配置过程通常已占用这些序号，必须改为查询后的新序号，并重新计算 CRC**；推荐脚本自动分配。已启动后重试必须保留原序号与参数。

单路 M1、逻辑正向，序号 1：完整命令携带 op=000A/ch=0000/arg=00000000，校验后直接执行。

```text
01 10 00 30 00 05 0A 00 01 00 0A 00 00 00 00 00 00 96 58
```

批量逻辑正向，序号 2；须上一批已结束且满足全部启动条件。

```text
01 10 00 30 00 05 0A 00 02 00 0B 00 00 00 00 00 00 92 68
```

读取每路完整八个结果寄存器：

```text
01 03 01 20 00 08 44 3A
01 03 01 60 00 08 45 EE
01 03 01 A0 00 08 45 D2
01 03 01 E0 00 08 44 06
```

响应结构：`01 03 10 [八个16位寄存器，共16字节] CRC_L CRC_H`。例如第一个数据字 `00 04` 是通过；随后原因字 `00 07` 则表示响应通过但位置保存失败。

同时读取 dirty/storage_error/pending_save：

```text
01 03 00 05 00 03 15 CA
```

| 自检中 STOP、STOP_ALL、任一路 BRAKE=1、可选按键 | 取消整批；被测位置无效；不启动后续通道；读取继续工作 |
| 余转不断、外力扰动其他通道 | 不确认停止，不进入下一路；两秒停止超时和整板运动锁生效 |
| 自检成功及取消后重启、试转中断电 | 成功保存后恢复位置；dirty 恢复位置失效、不续跑；结果重置 |
| dirty/clean 写入失败 | 前者不得释放刹车；后者报告存储错误，不能将通过当成保存成功 |
| 空白配置先批量检测，再填写四路减速比并 CONFIG | 检测不要求启用/减速比；配置后读回一致，重启仍保留四路配置；未使用通道仍禁用，自检结果重置不能解释为掉线 |
| 主循环繁忙、通信压力 | 示波器量测去程三脉冲、返程动态目标及每程 2000 ms 截止保护，检查没有重新拉起 PWM；确认实际中断延迟 |

参数集中在 `BSP/robot.h`：`ROBOT_SELFTEST_DUTY_MAX=100`、`ROBOT_SELFTEST_DUTY_STEP=10`、`ROBOT_SELFTEST_POWER_MS=300`、`ROBOT_SELFTEST_EDGES=3`、`ROBOT_SELFTEST_STOP_MS=2000`，控制周期 `ROBOT_CONTROL_MS=10`，静止窗口 `ROBOT_QUIET_MS=500`。修改参数后必须重新构建和验收；不通过上位机任意增大。

## 往返自检结果：转出去多少，再按实际计数返回

当前自检为：去程收到至少 3 个 FG → 刹车并统计余转 → 四路静止确认 → 按去程总脉冲 N 反向返回 → 刹车并统计返程余转 → 记录最终残差（仅诊断）。去程选择正向/负向，返程自动取反，沿用 inverted 配置。去程与返程各最多 2000 ms、最大 10%，整路总通电最多 4000 ms；去程 3 个加余转 2 个时，返程目标是 5 个，不按相同通电时间估算。

每次换向/完成前停止至少 500 ms 且四路连续 500 ms 无 FG；停止 2 s 仍无法确认静止则保持锁定。去程不足 3 个不返回，批量停稳后继续下一路；返程未达到目标超时，或捕获/其他通道活动/越界异常，中止整批。STOP/STOP_ALL/BRAKE=1 取消后不继续返回。无响应不能判定具体是未接、未供电、堵转还是 FG 故障。

两程达到脉冲目标并停稳、且无其他异常时报告通过；最终计数残差只记录和显示。当前位置按实际计数更新，不强制写回起点；成功保留原零点和原有效性，原本无效仍无效，失败/取消使被测位置失效。单线 FG 无法独立辨认真实转向，计数通过不保证机械精确回位。正常 MOVE 的 ±5°到位判据不变，自检残差不再设置失败阈值。

原 +20～+27 八个寄存器保留：总 FG 为往返含余转之和，+24 为去程通电毫秒，完成时间是整个该路往返结束时刻。原因追加 9=返回超时、10=历史返回偏差超限（保留编号，新版不产生）。状态 2/3 可能对应去程或返程，要结合新阶段字段判断。保存失败仍单独检查 0005～0007，不能把通过当成已经保存。

每路基址 0100/0140/0180/01C0，新增只读偏移（十六进制）：

| 偏移 | 内容 |
|---|---|
| +28 | 阶段：0 未开始、1 去程、2 去程停稳、3 返程、4 返程停稳、5 已结束 |
| +29 | 返程通电时间，uint16，ms |
| +2A～+2B | 去程总脉冲，含余转，uint32 |
| +2C～+2D | 返程总脉冲，含余转，uint32 |
| +2E～+2F | 相对起点有符号计数残差，int32，逻辑正方向为正 |

结果仅在 RAM，重启或相关配置变更后清除。未试转的通道阶段保持 0；已试转通道停稳后结束为 5。旧版固件没有 +28～+2F，查询可能返回地址异常；使用新增查询工具/报文前需确认已人工下载对应版本。

### Modbus：完整启动命令帧不变、取消额外提交，读取新增八个字段

逐条发送，无需提交（默认站号 01）：

| 通道 | TX：+28～+2F |
|---|---|
| M1 | `01 03 01 28 00 08 C5 F8` |
| M2 | `01 03 01 68 00 08 C4 2C` |
| M3 | `01 03 01 A8 00 08 C4 10` |
| M4 | `01 03 01 E8 00 08 C5 C4` |

应答 `01 03 10 [16 字节数据] CRC_L CRC_H`。数据依次是阶段两字节、返程时间两字节、去程脉冲四字节、返程脉冲四字节、残差四字节；多字值高字在前，负残差按 int32 二进制补码解析。仍需读取原 +20 状态、+21 原因和 +27 请求序号。阶段 5 不等于通过，必须核对状态为 4 且原因、存储标志无异常。

### CAN：读取新增字段

标准数据帧、DLC=8，node=1 时 TX ID=0x601、RX ID=0x581。每路四帧，每次两个寄存器：

| 通道 | 阶段/返程时间 | 去程脉冲 | 返程脉冲 | 残差 |
|---|---|---|---|---|
| M1 | `01 80 01 28 02 00 00 00` | `01 81 01 2A 02 00 00 00` | `01 82 01 2C 02 00 00 00` | `01 83 01 2E 02 00 00 00` |
| M2 | `01 84 01 68 02 00 00 00` | `01 85 01 6A 02 00 00 00` | `01 86 01 6C 02 00 00 00` | `01 87 01 6E 02 00 00 00` |
| M3 | `01 88 01 A8 02 00 00 00` | `01 89 01 AA 02 00 00 00` | `01 8A 01 AC 02 00 00 00` | `01 8B 01 AE 02 00 00 00` |
| M4 | `01 8C 01 E8 02 00 00 00` | `01 8D 01 EA 02 00 00 00` | `01 8E 01 EC 02 00 00 00` | `01 8F 01 EE 02 00 00 00` |

正常 RX 为 `81 tag 00 02 V0H V0L V1H V1L`。跨帧数据不是同时快照，宜在终态、同一请求序号下核对；运行中的实时数据仅供进度显示。


## 2026-10-10人工调整与故障4恢复更新

新增操作码12、能力寄存器0010和每路+30模式查询。故障4每次重新累计>10°构成事件：5000ms内1～2次到期自动清除，第3次重启窗口；保持停止、制动及位置无效。人工调整暂停该路故障4、冻结有符号位置，并独占整板运动。完整报文、ROS2服务、退出及保存步骤以[人工调整与故障4恢复](Robot_人工调整与故障4恢复.md)为准，历史日志不改写。
